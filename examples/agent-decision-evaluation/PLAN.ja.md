# 事前計画

対象フローは、過去の開発判断の理由・条件・変更経緯を調べ、出典付きで引き継ぐこと。
PR #286 の変更範囲CI案を不採用とした判断一件に限定する。既存 #348 はharnessの動作確認専用。
Core、公開API、CI設定、releaseは変更しない。新Issue、別の実装、次Goalは開始しない。

取得前に acquire.py の URLS を allowlist として保存する。PRの本文、全コメント・reviewの
非空本文と、判断時mainのCI/Makefile/AGENTS、案HEADのplannerを収録する。
最大20文書、抽出UTF-8合計1 MiB、response 2 MiB/件・合計10 MiB、collection 30件。
pagination、redirect、非公開認証、上限超過は停止する。可変本文は取得時点の内容であり、
過去時点の本文とは扱わない。固定commit資料とは別に出典とhashを残す。

回答開始前に質問9問、正解根拠、同じ短い要約、規則、seed、提示順、利用手順、binary、
入力・実行helperのhashを freeze.json に固定する。根拠引用はsnapshotに機械照合する。
質問と採点規則は回答開始後に変更しない。製品不具合は記録しCoreを変更しない。
評価器欠陥の修正では旧失敗を保持し、同じ新版で全条件を再評価する。

回答者A/B/C各3体、採点者3体を fresh context で独立起動する。同じmodel/effortを指定し、
実設定・agent ID・入力/出力hashを保存する。3体ずつのbatchで条件順を均衡する。
Aは要約と質問、Bはそれに平文と通常検索、Cは同じ原文のQZT/QZIとCLI手順・manifest。
各回答者は1条件だけを経験し、正解・他者回答・採点へアクセスしない。
親だけが共有コードを編集する。回答者は専用結果だけを書く。

各試行は起動から600秒、資料アクセス40回、各CLI30秒。上限後も取得済み回答と未完了を残す。
通常の検索言い換えを許すが、親は検索語・正解ヒントを伝えない。支援は全件記録する。
共通gatewayが資料アクセス、返却bytes、CLI呼出し、検索回数、時間を記録し制限する。
Agent全体は同一filesystemでありOS隔離と呼ばない。既存sandbox-execの利用可否を確認し、
実際のtool traceを監査する。資料外アクセス試行は無効として残す。

回答は共通JSON形式。全回答を固定して匿名化した後、J1〜J3が同じ規則・正解・匿名回答を
別々に全採点する。条件・model・他者採点を隠し、内容は編集しない。製品の痕跡は盲検の限界。
事実正確性、誤断定、根拠なし、主張と引用の対応、条件/撤回、適切なunknown、完遂を分離する。
食い違いは親が原文に照合し、解決不能なら評価不能を保つ。多数決を真実の根拠にしない。
引用実在・doc ID・byte範囲・SHAは別の機械検証。自己申告verifiedは合格根拠にしない。

B対Cを主要比較、Aは原文アクセス効果の参考。全試行と中央値/範囲、不一致を報告する。
同一hostの並列wall時間を製品単体の性能差とは呼ばない。token/課金実額は取得不可ならunknown。
保存量は原文、QZT、実際のQZI込みを比較し、初回pack/index/verifyと反復調査を分離する。
deep verify/indexは全体を読む。一般的な向上率、統計的有意性、人間評価、市場需要、第三者
検証、production-ready、External Validationの達成へ外挿しない。

受入は有効な12担当の実行記録、全失敗/unknown、再現手順、日本語比較レポート、根拠に基づく
次の開発判断一件。QZTの勝敗は条件にしない。対象テスト→セルフ/専門レビュー一件→直接指摘修正
→指摘範囲最終レビュー→必要な最終検証→Companion Gate後、最大1 PRを通常mergeしmain CI/securityを確認する。
