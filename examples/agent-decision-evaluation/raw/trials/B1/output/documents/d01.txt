## Why

PR CI currently runs the complete Rust suite on every change and repeats that work in coverage, even when a change has a bounded module or documentation impact. This increases elapsed time and billed compute. The optimization must not reduce failure detection when impact analysis is uncertain.

## Before

- Both stable and MSRV `check` lanes ran `make check`, including the full test suite.
- PR coverage ran the complete suite again.
- There was no machine-readable explanation of which tests were relevant or why full validation was required.
- Main was the only post-merge CI branch and there was no daily/manual full validation lane in `ci.yml`.

## After

- PRs always run formatting, Clippy, all-target compilation, docs, package, dependency policy, Windows release checks, public-example smoke, and security workflows.
- A CI-service-neutral planner reads rename/copy/delete-aware Git diffs, applies centralized dangerous-file rules, traverses reverse Rust module dependencies, recognizes public re-exports, and supplements them with explicit module/path mappings.
- Rust-specific analysis and commands live in `ci/adapters/`; the common planner contains no Rust dependency parser.
- Selected plans always add smoke tests. Missing revisions, malformed configuration, unknown files, stale mappings, shared contracts, dependency/build/test/CI changes, or analysis errors select the full suite.
- Main/release pushes, daily schedules, and manual dispatches force full validation. Full coverage remains on those lanes and is removed only from PRs to avoid executing all tests twice.
- Plans and execution summaries are uploaded for 14 days with revisions, changed/deleted files, affected modules, targets, fallback reason, target results, and duration.

## Key decisions

- Selected Cargo targets run sequentially in one job because parallel hosted jobs would duplicate compilation and can increase total compute cost for this single-crate repository.
- Adapter commands are argv arrays and selected target names are allowlisted, so changed filenames are never interpreted by a shell.
- Adapter corruption fails CI because no trustworthy full command can be recovered; impact-policy corruption produces a full plan.
- This PR changes CI policy itself, so its own impact plan intentionally falls back to the full suite.
