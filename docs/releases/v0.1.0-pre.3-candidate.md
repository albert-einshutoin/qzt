# v0.1.0-pre.3 candidate notes (unpublished)

Japanese: [v0.1.0-pre.3-candidate.ja.md](v0.1.0-pre.3-candidate.ja.md)

This is a **GitHub binary prerelease candidate**, not a published Release or a
crates.io upload. QZT v0.1 is a technical preview. The `qzt 0.1.0-pre.3`
distribution version does not change the QZT v0.1 container format. These notes
cover changes since the **published `v0.1.0-pre.2` tag commit**, including work
that preceded the latest `Unreleased` changelog entries. No pre.3 download URL
works until a separate owner-approved publication.

## Changes since pre.2

- CLI `pack`, `pack-docs`, `export`, `doc`, and `sidecar-rebuild` reject an
  input/output alias before writing and replace an existing file only after a
  successful temporary output and sync. Output symlinks are rejected. Windows
  read-only existing outputs are rejected without changing their bytes,
  attribute, or DACL; writable output access ACL/DACL is copied on replacement.
  See [file output safety](../CLI.md#file-output-safety) for failure and
  durability limits.
- Chunk Table/DLI counts and decoded DLI allocation are bounded before
  allocation. QZI granule chunk spans are checked against the bound QZT Chunk
  Table; candidate chunk counting merges intervals. Query, posting, physical
  decode, result-span, and index-build line work have explicit budgets. Search
  defaults to at most 10,000 results; calls that previously completed can now
  stop with a verified partial result or fail at a hard limit. See the
  [search CLI](../CLI.md#qzt-search-file-query-options)
  and [API stability notes](../API_STABILITY.md).
- Search checks returned token hits against original bytes and same-line
  boundaries. `source=verified_original_bytes` applies to each hit;
  `index_complete_declared` is the index's claim, while
  `index_coverage_verified` remains false. Reports distinguish normal
  completion, `stop_reason` on caps, and hard errors.
- The public Writer refuses nonempty sinks, checks that successful output can
  be opened by a default Reader, and poisons a failed streaming write; a
  caller must discard its partial generic sink. This is distinct from CLI
  atomic file replacement. Complete Rust struct literals may need new
  `ResourceLimits`, search options/metrics/report, index-build options, and
  `VerifyReport` fields; use defaults or update the literals explicitly.
- `VerifyReport` now separates structurally checked chunks, compressed
  checksum checks, decoded chunks/bytes, original checksum verification, and
  optional index states by verification level. `qzt attest` now emits canonical
  `qzt-attestation-v1`. See [pre.2 migration](v0.1.0-pre.3-migration.md)
  and [attestation](../CLI.md#attestation-canonical-form).
- Since pre.2, the CLI also gained sidecar inspection and the `version` alias,
  while the documentation gained complete English/Japanese CLI references and
  a reproducible release tour. The published pre.2 README install/tour remains
  pinned to pre.2 until a real pre.3 Release exists.
- The [September 2026 CLI cost report](../benchmarks/2026-09-cli-cost.md)
  measured development code on synthetic 100 MiB input under stated macOS
  hardware/cache/concurrency conditions. It is not a pre.3 asset measurement,
  production workload result, or performance guarantee. No #27 optimization
  is included in this candidate.

## Candidate evidence and publication boundary

The read-only [candidate workflow](../../.github/workflows/release-candidate.yml)
uses cargo-dist 0.31.0 to produce four native target archives, checksums,
installers, and a source archive without creating a tag or Release. Its 14-day
CI artifacts record the exact source SHA, runner, Rust toolchain, archive and
extracted-binary hashes, and a small end-to-end smoke. PR rehearsal evidence
and the later exact-main-SHA candidate run are separate. The candidate issue
records their run URLs and results after execution. An installer references
the future tag URL; downloading through it cannot be tested before release.
Each native archive has its own `.sha256` sidecar. In this cargo-dist global
build, `sha256.sum` covers `source.tar.gz`; the four native sidecars are retained
in their respective CI artifacts and are checked separately.

Owner approval, tag creation/push, protected release environment approval,
Release creation, and real published-asset checks remain in the
[release runbook](../RELEASE.md#pre3-candidate-publication-after-owner-approval).
