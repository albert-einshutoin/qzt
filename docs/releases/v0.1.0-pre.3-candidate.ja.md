## pre.2以降の変更

- CLIの`pack`、`pack-docs`、`export`、`doc`、`sidecar-rebuild`は入力と出力が
  同一ファイルなら書込み前に拒否し、一時出力と同期が成功してから既存出力を
  置換します。出力symlinkは拒否します。Windowsのreadonly既存出力は内容・属性・
  DACLを変えず拒否し、書込み可能な出力の置換ではaccess ACL/DACLを複製します。
  失敗時と永続化の限界は[CLIのfile出力の保護](../CLI.ja.md#file出力の保護)
  を参照してください。
- Chunk Table/DLIの件数とDLI展開配列の確保量を確保前に検証します。QZIの
  granule chunk範囲をQZT Chunk Tableへ照合し、候補chunk数は区間統合で計算します。
  query、posting、物理展開、result span、index構築時の行長に予算を設けました。
  検索結果の既定上限は10,000件で、以前成功した呼出しも検証済み部分結果で停止、
  またはhard limitで失敗する場合があります。詳細は[CLI](../CLI.ja.md)と
  [API安定性](../API_STABILITY.md)を参照してください。
- 検索hitは原文byteと同一行の境界で照合します。
  `source=verified_original_bytes`は個々のhitの性質であり、
  `index_complete_declared`はindexの宣言、`index_coverage_verified`は引き続き
  falseです。正常終了、capによる`stop_reason`、hard errorを区別します。
- 公開Writerは非空sinkを拒否し、成功した出力がdefault Readerで読めることを
  検査します。streaming中の失敗後はpoisonedとなり、generic sinkの部分byteは
  呼出元が破棄します。これはCLIのatomic file replacementとは別の契約です。
  Rust APIの完全な構造体リテラルでは`ResourceLimits`、検索関連option/report、
  index build option、`VerifyReport`の新fieldへの対応が必要です。
- `VerifyReport`は構造検査したchunk、圧縮checksum、展開chunk/byte、原文
  checksum、任意indexの状態を検証level別に表します。`qzt attest`は正準
  `qzt-attestation-v1`を出力します。[移行説明](v0.1.0-pre.3-migration.ja.md)
  と[attestation](../CLI.ja.md#アテステーション正準形)を参照してください。
- pre.2以降に`inspect-sidecar`と`version` alias、英日CLI参照、再現可能な
  release tourを追加しました。公開済みpre.2のREADME Installとtourは、実際の
  pre.3公開前はpre.2に固定していました。
- [2026年9月のCLI費用計測](../benchmarks/2026-09-cli-cost.md)は、合成100 MiB入力、
  記録したmacOSの機器・cache・同時実行条件での開発版の結果です。pre.3配布asset
  や本番workloadの計測、性能保証ではありません。#27の最適化は含みません。

## 候補の証拠と公開境界

読み取り権限のみの[候補workflow](../../.github/workflows/release-candidate.yml)は
cargo-dist 0.31.0で4つのnative archive、checksum、installer、source archiveを
生成します。tagやReleaseは作成しません。14日保持のCI artifactに正確なsource
SHA、runner、Rust toolchain、archiveと展開binaryのhash、小さなE2E smokeを
記録します。PR予行と、merge後の正確なmain SHAによる最終候補検証は別の証拠です。
実行後のrun URLと結果は候補Issueへ記録します。installerは当時未公開のtag URLを
参照していたため、実downloadは候補段階では検証していません。
各native archiveには個別の`.sha256` sidecarがあります。このcargo-distの
global buildの`sha256.sum`は`source.tar.gz`を対象とし、4 targetのsidecarは
それぞれのCI artifactに保管して個別に照合します。

owner承認、tag作成・push、保護されたrelease environmentの承認とRelease作成は
後続の公開工程で実施しました。公開assetの実検証は[#313](https://github.com/albert-einshutoin/qzt/issues/313)に
別記し、この候補証拠へ上書きしません。
