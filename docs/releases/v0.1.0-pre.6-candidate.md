The final source is the exact W2 merge SHA, not this earlier basis or PR SHA.

## W2 acceptance

Issue [#338](https://github.com/albert-einshutoin/qzt/issues/338) owns candidate evidence.
After reviewed PR CI/security and merge, manually dispatch `release-candidate.yml`
with `candidate_sha=<full merge SHA>`. Require every job to succeed:

- Four native archive builds: macOS ARM64/Intel, Linux x64 and Windows x64.
  Archive checksum, binary hash/version, then mandatory `public-workflow-v1`:
  pack/info/QZI/search/context/deep verify/export with exact original bytes.
- Hit coordinates, document ID, context bytes/budget fragments, unknown search
  coverage, zero/capped zero and corrupt sidecar remain independently observable.
- All 14 frozen golden Core vectors: open/deep success or recorded failure stage,
  original-byte export for all valid vectors, and unsupported QZT version rejection.
  Existing `phase22_vectors` additionally checks frozen hashes and optional indexes.
- F1 Rust gate: `phase2_fixed`, `phase8_reader_core`, `phase13_sidecar`,
  `phase22_vectors` (with `internal-testing`), and `sidecar::manifest_tests`. This includes unknown required block
  rejection and current token/ngram QZI v1/v2 support, not future-format support.
- Existing pre.3/current candidate cross-reader matrix: Deep verify/export/search,
  canonical attestation bytes and same-container token/ngram QZI bytes.
- Native Windows PowerShell installer rehearsal uses its supported
  `QZT_DOWNLOAD_URL` set explicitly to a loopback server serving candidate files.
  The unmodified installer runs without credentials/PATH changes, installed binary
  hash equals the checked archive binary, and the same C4 profile succeeds.
  This is candidate installation evidence; it does not test a public Release URL.
- Global checksum/source-tree and pre-host assembly checks reuse the protected
  release workflow's build/read/copy path. No tag, hosting or publication in W2.

Retain run/attempt/source and per-target archive/binary hashes. CI JSON artifacts
expire after 14 days; preserve their records when reporting W2/W3.

## W3 acceptance and failure handling

Only after W2 succeeds, create an annotated tag at that exact source SHA and use
the ordinary protected tag-only Release workflow. Publish the next preview,
then verify all 14 assets downloaded from the actual GitHub Release URLs.
Require tag/source/run binding, GitHub digests, archive sidecars, exact source tree,
and all four native archive **and installed** C4 workflows, including native
PowerShell. Do not set `QZT_DOWNLOAD_URL` for this public verification.

The public version in README/README.ja, CLI references, workflow guides and release
announcement must agree. Record candidate and public hashes separately: distinct
builds need not have identical hashes. Each installed binary must match its own
selected archive, and every public digest must match the Release metadata.

After any publication defect, retain the failed run/logs and stop. Do not overwrite
assets, move the tag, silently republish, or claim G1/M1 complete.

## Limits

Passing proves the selected assets and bounded fixtures, not exhaustive search,
external provenance, third-party adoption, large-data operating limits or performance.
Format remains QZT v0.1 with zstd; no format/schema/public API change or multi-codec
support is included. No crates.io publication is part of these preview gates.
