# 公開済みpre.2 binaryからpre.3への移行

English: [v0.1.0-pre.3-migration.md](v0.1.0-pre.3-migration.md)

[`v0.1.0-pre.3` GitHub prerelease](https://github.com/albert-einshutoin/qzt/releases/tag/v0.1.0-pre.3)は、
製品commit `017d4d19739800773ab6a54adf636ff5a43ec1fc`から公開済みです。
[現行READMEの導入とツアー](../../README.ja.md)と
[公開assetの検証記録](https://github.com/albert-einshutoin/qzt/issues/313)を参照してください。
先行する候補buildと別のhashは[#311](https://github.com/albert-einshutoin/qzt/issues/311)に
保存します。保存形式`qzt-0.1`とCLI配布版`qzt 0.1.0-pre.3`は異なる版軸です。
既存の正常なQZT v0.1 vectorのbyte列は変わらず、公開binaryでも読み取れます。

## file出力とWriter

CLIのfile出力は、hard linkや大文字小文字aliasを含む入力との同一性、および
出力symlinkを拒否します。Windowsのreadonly既存出力は書込み前に、内容・属性・
DACLを変えずに拒否します。書込み可能な既存出力の置換ではaccess ACL/DACLを
維持し、新規出力・stdoutにはそれぞれ別の契約があります。generic Writerは
非空sinkを拒否し、streaming失敗後の部分出力は呼出元が破棄します。成功出力は
default Readerの上限内で検査します。置換後の永続化診断は「置換済み、dir entryの
永続化未確認」を意味します。Windowsの同一volume renameでも停電後のdir entryの
永続性は未確認です。[CLI file出力](../CLI.ja.md#file出力の保護)と
[Writer API](../API_STABILITY.md#writer-api-consolidation)を参照してください。

## 検証とattestation

pre.2のversionなしattestationは、元のbyte列と署名・timestampを**一組のまま**
保存してください。候補の正準`qzt-attestation-v1`は異なるbyte列なので、
再生成時には新たに署名・timestampを取得します。attestationの差だけではQZT
原文が変わった証拠になりません。[正準形](../CLI.ja.md#アテステーション正準形)と
[署名guide](../guides/attestation.md)を参照してください。

`VerifyReport.checked_chunks`は構造検査したChunk Table entry数であり、
展開chunk数ではありません。`compressed_checksum_chunks`は圧縮payloadの
checksum検査数、`decoded_chunks`と`decoded_bytes`は実展開量、
`original_checksum_verified`は原文全体のchecksumを再計算したかを表します。
Quick／Normal／Deepは証拠の深さが異なるため、復元原文の完全性を主張する前に
Deepを要求してください。任意indexの状態は別fieldです。Rustの完全な
`VerifyReport`リテラルは新fieldが必要です。[CLI verify](../CLI.ja.md)と
[API説明](../API_STABILITY.md)を参照してください。

## 検索と資源上限

返った個々のhitは原文byteへ照合されますが、`index_complete_declared=true`は
indexの宣言を示すだけです。`index_coverage_verified=false`のとき0 hitは
原文に一致箇所がない証明になりません。`capped=false`で`stop_reason=null`は
検査した候補集合の通常終了、`capped=true`と名前付き`stop_reason`は検証済み
部分結果です。query、posting、行長等のhard limitはexit 1のErrorです。
[CLI search](../CLI.ja.md)と[検索運用](../guides/search-operations.ja.md)
を参照してください。

`max_search_results`の既定値は10,000です。query、posting、candidate、
物理・論理展開、DLI allocation、index構築時の行長の予算により、pre.2で
成功していた呼出しが途中停止または拒否される場合があります。必要な上限だけを
資源costを確認して引き上げてください。Rust APIで`ResourceLimits`、
`SearchOptions`、`SearchReport`、`SearchMetrics`、`TokenIndexBuildOptions`、
`NgramIndexBuildOptions`、`VerifyReport`を完全な構造体リテラルで作る場合は
新fieldへの追従が必要です。`Default`からの構造体更新も使えます。

## 公開assetと候補証拠の保存

実際の[Release](https://github.com/albert-einshutoin/qzt/releases/tag/v0.1.0-pre.3)から
archiveと対応する`.sha256`を取得し、展開前に照合して展開binaryの絶対pathを
実行します。[読み取り専用の公開物verifier](../../scripts/verify-published-release.py)は
native smokeと公開installerから一時先への導入も確認します。release workflowは
不変tagからassetを再buildするため、候補archiveと公開archiveのhashは同一とは
限りません。archiveとbinaryの双方を比較し、[#311](https://github.com/albert-einshutoin/qzt/issues/311)の
候補結果を[#313](https://github.com/albert-einshutoin/qzt/issues/313)の公開結果へ
代用しません。pre.2の旧attestationと#311の候補証拠は履歴として保持します。
今回のGitHub prereleaseではcrates.ioへの公開は行っていません。
